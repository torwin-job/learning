### **Архитектурные решения для рефакторинга Vue-проекта (простые и эффективные)**  

Рефакторинг Vue-приложения должен улучшить структуру кода, сделать его более поддерживаемым и масштабируемым. Вот лучшие подходы для небольших и средних проектов:  

---

## **1. Переход на Composition API (вместо Options API)**  
**Проблема:** Устаревший или смешанный код (Options + Composition API).  
**Решение:** Постепенно переписать компоненты на Composition API (`<script setup>`).  

### **Пример рефакторинга:**  
**До (Options API):**  
```vue
<script>
export default {
  data() {
    return { count: 0 }
  },
  methods: {
    increment() { this.count++ }
  }
}
</script>
```  

**После (Composition API):**  
```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const increment = () => count.value++
</script>
```  
**Плюсы:**  
- Лучшая организация логики.  
- Упрощенное переиспользование кода (через `composables`).  

---

## **2. Вынесение логики в Composables**  
**Проблема:** Большие компоненты с кучей методов и состояний.  
**Решение:** Разделить логику на отдельные файлы (`useХХХ.js`).  

### **Пример:**  
**`composables/useCounter.js`**  
```javascript
import { ref } from 'vue'

export function useCounter() {
  const count = ref(0)
  const increment = () => count.value++

  return { count, increment }
}
```  

**Компонент:**  
```vue
<script setup>
import { useCounter } from './composables/useCounter'
const { count, increment } = useCounter()
</script>
```  
**Плюсы:**  
- Чистые компоненты.  
- Логику можно тестировать отдельно.  

---

## **3. Централизованное управление состоянием (Pinia вместо Vuex)**  
**Проблема:** Громоздкий Vuex или хаотичное использование `props`/`emits`.  
**Решение:** Переход на **Pinia** – более простой и современный стейт-менеджер.  

### **Пример:**  
**`stores/counterStore.js`**  
```javascript
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  actions: {
    increment() { this.count++ }
  }
})
```  

**Использование в компоненте:**  
```vue
<script setup>
import { useCounterStore } from '@/stores/counterStore'
const counter = useCounterStore()
</script>

<template>
  <button @click="counter.increment">{{ counter.count }}</button>
</template>
```  
**Плюсы:**  
- Проще, чем Vuex.  
- Поддержка TypeScript из коробки.  

---

## **4. Единая структура папок**  
**Проблема:** Файлы разбросаны хаотично (`components`, `views`, `utils` вперемешку).  
**Решение:** Четкая структура:  

```
src/
├── assets/          # Статика (картинки, шрифты)
├── components/      # Переиспользуемые UI-компоненты
├── composables/     # Логика (хуки)
├── stores/          # Pinia-сторе
├── router/          # Маршруты
├── views/           # Страницы
├── utils/           # Вспомогательные функции
└── App.vue          # Корневой компонент
```  

---

## **5. Автоматический импорт компонентов (unplugin-vue-components)**  
**Проблема:** Ручные импорты (`import Button from '@/components/Button.vue'`).  
**Решение:** Настроить автоматический импорт.  

### **Настройка в `vite.config.js`:**  
```javascript
import Components from 'unplugin-vue-components/vite'

export default {
  plugins: [
    Components({
      dirs: ['src/components'], // Автоимпорт из этой папки
    }),
  ],
}
```  
Теперь компоненты можно использовать без `import`:  
```vue
<template>
  <MyButton /> <!-- Автоматически загрузится из components/MyButton.vue -->
</template>
```  

**Плюсы:**  
- Меньше boilerplate-кода.  
- Удобнее рефакторить.  

---

## **6. Типизация с TypeScript**  
**Проблема:** Динамическая типизация → сложно ловить ошибки.  
**Решение:** Постепенно внедрять TypeScript.  

### **Пример типизированного компонента:**  
```vue
<script setup lang="ts">
interface Props {
  title: string
  count?: number
}

const props = defineProps<Props>()
</script>
```  

**Плюсы:**  
- Лучшая поддержка кода.  
- IDE подсказывает типы.  

---

## **7. Оптимизация производительности**  
**Проблема:** Медленные страницы из-за лишних ререндеров.  
**Решения:**  
- Использовать `v-once` для статичных элементов.  
- Ленивая загрузка компонентов (`defineAsyncComponent`).  
- Оптимизировать `v-for` с `:key`.  

### **Пример ленивой загрузки:**  
```vue
<script setup>
import { defineAsyncComponent } from 'vue'

const HeavyComponent = defineAsyncComponent(() =>
  import('./HeavyComponent.vue')
</script>
```  

---

## **Вывод: какой рефакторинг применить?**  
| Проблема               | Решение                                       |
| ---------------------- | --------------------------------------------- |
| Устаревший Options API | Переход на Composition API (`<script setup>`) |
| Большие компоненты     | Вынос логики в `composables/`                 |
| Громоздкий Vuex        | Замена на Pinia                               |
| Хаотичная структура    | Единая система папок                          |
| Ручные импорты         | Настройка `unplugin-vue-components`           |
| Нет типов              | Внедрение TypeScript                          |

**Совет:** Начинайте с самого критичного (например, Pinia или Composables), затем постепенно улучшайте остальное.
