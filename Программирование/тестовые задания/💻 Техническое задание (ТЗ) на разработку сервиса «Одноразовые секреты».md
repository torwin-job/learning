## 📌 Суть задачи

Разработать HTTP-сервис на **FastAPI**, который позволяет хранить конфиденциальные данные (**секреты**).

🔹 **Ключевая особенность**: Секрет доступен **только один раз** — после первого запроса он становится недоступным.

---

## 🔥 Кеширование

✅ Созданный **секрет** должен находиться в серверном кеше **не менее 5 минут** с момента создания.

---

## 🔐 Требования к хранению и безопасности

✅ **Шифрование:** Все секреты должны храниться **в зашифрованном виде** (не в открытом тексте).

✅ **Запрет кеширования на клиенте:** Нужно выставить соответствующие **HTTP-заголовки**, запрещающие кеширование **на стороне клиента и промежуточных прокси**.

---

## 🛢 Работа с базой данных (PostgreSQL)

Помимо кеширования, сервис должен **хранить данные в PostgreSQL**.

### 🔍 Рекомендуемые данные для хранения:

- Логи действий (**создание, чтение, удаление**).
    
- Время запроса, **IP-адрес**.
    
- Дополнительные сущности (например, **учётные записи пользователей, аудит, статистика использования** и др.).
    

📌 **Структура базы данных остается на усмотрение разработчика**, главное — обеспечить возможность **расширения сервиса**.

## 🛠 Описание API-эндпоинтов

### 1️⃣ Создание секрета

📌 **Метод:** `POST /secret`

📌 **Тело запроса (JSON):**

```json
{
  "secret": "доступ_к_конфиденциальным_данным",
  "passphrase": "my_passphrase",
  "ttl_seconds": 3600
}
```

📌 **Пример ответа:**

```json
{
  "secret_key": "уникальный_идентификатор"
}
```

✅ **После создания:**

- **Сохранить секрет**.
    
- **Залогировать создание** (ID секрета, время, IP-адрес, TTL и т. д.).
    

---

### 2️⃣ Получение секрета

📌 **Метод:** `GET /secret/{secret_key}`

📌 **Пример ответа:**

```json
{
  "secret": "доступ_к_конфиденциальным_данным"
}
```

✅ **После получения:**

- **Секрет удаляется** и становится **недоступным** для последующих запросов.
    
- **Логируется факт выдачи** (время, IP-адрес и т. д.).
    

---

### 3️⃣ Удаление секрета

📌 **Метод:** `DELETE /secret/{secret_key}`

📌 **Пример ответа:**

```json
{
  "status": "secret_deleted"
}
```

✅ **После удаления:**

- **Секрет становится недоступным** даже при первом запросе.
    
- **Логируется факт удаления** (ключ секрета, время, IP-адрес и др.).
    

---

## ⏳ Дополнительные требования

✅ **Поддержка TTL:**

- По истечении `ttl_seconds` **секрет автоматически удаляется**.
    
- Должна быть **очистка просроченных секретов**.
    

✅ **Безопасность:**

- Корректная работа с чувствительными данными (**шифрование секретов**).
    
- **Запрет кеширования** на клиенте через заголовки:
    

```http
Cache-Control: no-cache, no-store, must-revalidate
Pragma: no-cache
Expires: 0
```

✅ **Работа с PostgreSQL:**

- Логирование всех операций (**создание, получение, удаление**).
    
- Возможность **расширения хранения данных**.
