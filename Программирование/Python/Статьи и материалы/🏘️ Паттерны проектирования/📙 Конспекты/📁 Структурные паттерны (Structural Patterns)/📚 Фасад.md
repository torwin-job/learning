# **Полный конспект по паттерну Facade (Фасад) на Python**  

[[Подробный пример Facade]]
## **1. Назначение паттерна Facade**  
**Фасад** — это структурный паттерн, который предоставляет **простой интерфейс** к сложной системе классов, библиотеке или фреймворку. Он:  
✔ **Скрывает сложность** системы за упрощенным API.  
✔ **Уменьшает зависимости** клиентского кода от внутренних компонентов.  
✔ **Облегчает поддержку** и модификацию кода.  

📌 **Аналогия из жизни**:  
Интерфейс банкомата (Фасад) скрывает сложность банковской системы (проверка баланса, списание средств, логирование и т. д.).  

---

## **2. Проблема, которую решает Facade**  
❌ **Слишком сложный интерфейс** системы (например, работа с базой данных, API, микросервисами).  
❌ **Клиентский код зависит от внутренней логики**, что усложняет изменения.  
❌ **Трудно тестировать** из-за множества зависимостей.  

**Решение**:  
→ Создать **единую точку входа** (фасад), который делегирует вызовы нужным компонентам.  

---

## **3. Структура Facade**  

```
┌───────────────────┐       ┌───────────────────┐
│     Клиент       │──────>│      Фасад        │
└───────────────────┘       └───────────────────┘
                                    │
                                    ▼
┌───────────────────┐ ┌───────────────────┐ ┌───────────────────┐
│  Подсистема "A"   │ │  Подсистема "B"   │ │  Подсистема "C"   │
└───────────────────┘ └───────────────────┘ └───────────────────┘
```

- **Фасад** знает, каким классам подсистемы перенаправить запрос.  
- **Клиент** использует только фасад, не зная о сложности внутри.  

---

## **4. Пример кода на Python**  

### **🔹 Сложная подсистема (без фасада)**  
Допустим, у нас есть:  
- **Database** – работа с БД  
- **AuthService** – аутентификация  
- **Logger** – логирование  

```python
class Database:
    def connect(self):
        print("Подключение к базе данных")

    def disconnect(self):
        print("Отключение от базы данных")

    def execute_query(self, query):
        print(f"Выполнение запроса: {query}")

class AuthService:
    def login(self, username, password):
        print(f"Аутентификация пользователя: {username}")

    def logout(self):
        print("Выход из системы")

class Logger:
    def log(self, message):
        print(f"Лог: {message}")
```

**Проблема**: Клиенту нужно управлять всеми классами вручную.  

```python
db = Database()
auth = AuthService()
logger = Logger()

db.connect()
auth.login("user123", "qwerty")
logger.log("Пользователь вошел в систему")
db.execute_query("SELECT * FROM users")
auth.logout()
db.disconnect()
```

👉 **Минусы**:  
- Много кода для простых операций.  
- При изменении логики придется править **все места**, где используется подсистема.  

---

### **🔹 Решение: Добавляем Facade**  

```python
class SystemFacade:
    def __init__(self):
        self.db = Database()
        self.auth = AuthService()
        self.logger = Logger()

    def login_user(self, username, password):
        self.db.connect()
        self.auth.login(username, password)
        self.logger.log(f"Пользователь {username} вошел")

    def logout_user(self):
        self.auth.logout()
        self.logger.log("Пользователь вышел")
        self.db.disconnect()

    def make_query(self, query):
        self.db.execute_query(query)
        self.logger.log(f"Выполнен запрос: {query}")
```

**Теперь клиентский код становится простым**:  

```python
system = SystemFacade()

system.login_user("user123", "qwerty")  # Всё работает "под капотом"
system.make_query("SELECT * FROM users")
system.logout_user()
```

**Вывод**:  
```
Подключение к базе данных  
Аутентификация пользователя: user123  
Лог: Пользователь user123 вошел  
Выполнение запроса: SELECT * FROM users  
Лог: Выполнен запрос: SELECT * FROM users  
Выход из системы  
Лог: Пользователь вышел  
Отключение от базы данных  
```

## **5. Плюсы и минусы Facade**  

### **✅ Преимущества**  
✔ **Упрощает использование** сложных систем.  
✔ **Уменьшает связность** между клиентом и подсистемой.  
✔ **Можно постепенно внедрять** – сначала фасад, потом рефакторинг подсистемы.  

### **❌ Недостатки**  
❌ **Фасад может стать "божественным объектом"**, если взять на себя слишком много.  
❌ **Дополнительный слой абстракции** (не всегда нужен в простых случаях).  

---

## **6. Где применяется Facade?**  
🚀 **ORM-библиотеки** (Django ORM, SQLAlchemy) – скрывают SQL-запросы.  
🚀 **Микросервисные API** – единый шлюз для нескольких сервисов.  
🚀 **Работа с файлами** (например, `open()`, `json.load()` – это фасады).  
🚀 **Графические библиотеки** (например, `matplotlib.pyplot` упрощает сложный API).  

---

## **7. Отличие Facade от других паттернов**  
- **Adapter** → **Преобразует интерфейсы**, чтобы они работали вместе.  
- **Proxy** → **Контролирует доступ** к объекту (кеширование, ленивая загрузка).  
- **Facade** → **Упрощает интерфейс**, но не меняет поведение.  

---

## **8. Вывод**  
**Когда использовать Facade?**  
🔹 Если система **слишком сложная** и нужно дать клиенту простой способ работы.  
🔹 Если хотите **снизить зависимость** кода от внутренней реализации.  

**Пример из Python**:  
```python
import sqlite3

# Без фасада:
conn = sqlite3.connect("db.sqlite3")
cursor = conn.cursor()
cursor.execute("SELECT * FROM users")
conn.close()

# С фасадом (например, Django ORM):
users = User.objects.all()  # Внутри: подключение, запрос, закрытие
```  

**Facade** – это **"удобная обёртка"** для сложных систем. 🚀
