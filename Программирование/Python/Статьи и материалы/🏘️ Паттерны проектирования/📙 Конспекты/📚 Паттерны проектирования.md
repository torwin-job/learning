Это список паттернов проектирования (Design Patterns), которые помогают решать распространённые проблемы в разработке программного обеспечения. Каждый паттерн предлагает стандартное решение для определённого типа задач.  

---

### **3. Factory (Фабрика)**  [[📚 Factory Method]]
**Для чего:** Создание объектов без указания их конкретных классов.  
**Как работает:**  
- Определяется интерфейс для создания объекта, но подклассы решают, какой класс инстанцировать.  
- Пример: `CarFactory.createCar()` может возвращать `Sedan`, `SUV` или `ElectricCar` в зависимости от логики.  

**Плюсы:**  
- Гибкость: можно добавлять новые типы объектов, не меняя основной код.  
- Инкапсуляция: логика создания скрыта от клиента.  

---

### **4. Prototype (Прототип)**  
**Для чего:** Создание копий объектов без привязки к их классам.  
**Как работает:**  
- Объекты реализуют метод `clone()`, который возвращает копию себя.  
- Пример: клонирование графического элемента (например, кнопки) вместо создания нового.  

**Плюсы:**  
- Экономит ресурсы, если создание объекта дорогое.  
- Упрощает создание сложных объектов.  

---

### **5. Facade (Фасад)**  [[📚 Фасад]]
**Для чего:** Упрощение взаимодействия с сложной системой через единый интерфейс.  
**Как работает:**  
- Скрывает сложные детали подсистем за простым API.  
- Пример: `Computer.start()` включает CPU, RAM, HDD и т.д., но пользователь видит только одну кнопку.  

**Плюсы:**  
- Уменьшает сложность для клиента.  
- Изолирует изменения в подсистеме.  

---

### **6. Adapter (Адаптер)**  [[📚 Адаптер]]
**Для чего:** Совмещение несовместимых интерфейсов.  
**Как работает:**  
- Обёртывает один интерфейс в другой, чтобы они могли работать вместе.  
- Пример: адаптер для подключения USB-C к HDMI.  

**Плюсы:**  
- Позволяет повторно использовать старый код с новой системой.  

---

### **7. Flyweight (Легковес)**  
**Для чего:** Экономия памяти за счёт разделения общих данных.  
**Как работает:**  
- Разделяет состояние на внутреннее (общее) и внешнее (уникальное).  
- Пример: в текстовом редакторе символы (например, буква "А") хранятся один раз, а позиции и стили — отдельно.  

**Плюсы:**  
- Экономит память при большом количестве объектов.  

---

### **8. Builder (Строитель)**  
**Для чего:** Пошаговое создание сложных объектов.  
**Как работает:**  
- Отделяет конструирование объекта от его представления.  
- Пример: `PizzaBuilder` может добавлять ингредиенты шаг за шагом (`addCheese()`, `addPepperoni()`).  

**Плюсы:**  
- Позволяет создавать разные конфигурации объекта.  
- Упрощает код создания.  

---

### **9. Bridge (Мост)**  
**Для чего:** Разделение абстракции и реализации для независимого изменения.  
**Как работает:**  
- Абстракция (например, `RemoteControl`) и реализация (`Device`) связаны через композицию, а не наследование.  
- Пример: пульт (абстракция) может работать с разными устройствами (TV, Radio).  

**Плюсы:**  
- Уменьшает связанность классов.  
- Позволяет изменять их независимо.  

---

### **10. Composite (Компоновщик)**  
**Для чего:** Единообразная работа с отдельными объектами и их группами.  
**Как работает:**  
- Объекты объединяются в древовидные структуры.  
- Пример: файловая система (файл и папка реализуют один интерфейс `FileSystemNode`).  

**Плюсы:**  
- Упрощает работу с иерархиями.  
- Позволяет рекурсивно обрабатывать структуры.  

---

### **11. Proxy (Заместитель)**  [[📚 Proxy]]
**Для чего:** Контроль доступа к объекту или добавление логики.  
**Как работает:**  
- Создаётся объект-заменитель, который перехватывает вызовы к оригиналу.  
- Примеры:  
  - Ленивая загрузка (`LazyProxy`).  
  - Защита доступа (`SecurityProxy`).  
  - Кеширование (`CacheProxy`).  

**Плюсы:**  
- Позволяет добавлять функциональность без изменения исходного кода.  

---

### **Вывод**  
Эти паттерны помогают:  
- Уменьшать связанность кода.  
- Повышать гибкость и расширяемость.  
- Решать конкретные проблемы проектирования.  

Их стоит применять там, где они действительно нужны, а не "на всякий случай".
