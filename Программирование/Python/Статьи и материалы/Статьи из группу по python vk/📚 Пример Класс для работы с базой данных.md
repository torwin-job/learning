Вот конкретный пример с пошаговым объяснением, показывающий разницу между изначальным подходом и улучшенной версией с фабричными методами.



---

## 📌 Пример: Класс для работы с базой данных

### 🔧 **Исходная реализация (проблемная)**

```python
class DatabaseClient:
    """Проблемная версия - создаёт соединение внутри __init__"""
    
    def __init__(self, host: str, port: int):
        self._connection = PostgreSQLConnection(host, port)  # Жёсткая привязка
    
    def get_user(self, user_id: int) -> User:
        return self._connection.execute(f"SELECT * FROM users WHERE id = {user_id}")
```

**Проблемы:**
1. Невозможно подменить `PostgreSQLConnection` на mock в тестах
2. Если нужно подключиться к SQLite или MySQL - придется менять код класса
3. Невозможно асинхронно инициализировать соединение

---

### 🛠 **Улучшенная версия (с фабричными методами)**

```python
class DatabaseClient:
    """Улучшенная версия с внедрением зависимости"""
    
    def __init__(self, connection: DatabaseConnection):
        self._connection = connection  # Принимаем готовое соединение
    
    @classmethod
    def create_postgresql(cls, host: str, port: int) -> 'DatabaseClient':
        """Фабричный метод для PostgreSQL"""
        return cls(PostgreSQLConnection(host, port))
    
    @classmethod
    def create_sqlite(cls, path: str) -> 'DatabaseClient':
        """Альтернативный фабричный метод для SQLite"""
        return cls(SQLiteConnection(path))
    
    @classmethod
    async def create_async(cls, host: str, port: int) -> 'DatabaseClient':
        """Асинхронный фабричный метод"""
        conn = await AsyncPostgreSQLConnection.create(host, port)
        return cls(conn)
    
    def get_user(self, user_id: int) -> User:
        return self._connection.execute(f"SELECT * FROM users WHERE id = {user_id}")
```

---

### 🎯 **Как это использовать?**

#### 1. Обычное создание объекта:
```python
# Через фабричный метод
client = DatabaseClient.create_postgresql("localhost", 5432)

# Или с готовым соединением
custom_conn = CustomConnection()
client = DatabaseClient(custom_conn)
```

#### 2. Для тестирования:
```python
class FakeConnection:
    def execute(self, query):
        return User(id=1, name="Test User")

# Тест не зависит от реальной БД
def test_get_user():
    client = DatabaseClient(FakeConnection())
    user = client.get_user(1)
    assert user.name == "Test User"
```

#### 3. Асинхронная инициализация:
```python
async def main():
    client = await DatabaseClient.create_async("db.example.com", 5432)
    user = client.get_user(1)
```

---

### 📊 **Сравнение подходов**

| Критерий               | Изначальный подход | Фабричные методы |
|------------------------|--------------------|------------------|
| Гибкость               | ❌ Жёсткая привязка | ✅ Разные варианты |
| Тестируемость          | ❌ Сложно mock'ать | ✅ Легко подменить |
| Асинхронность          | ❌ Невозможно      | ✅ Поддерживается |
| Разные реализации БД   | ❌ Только PostgreSQL | ✅ Любая БД |

---

Этот подход особенно полезен в реальных проектах, где важны:
- Возможность тестирования
- Поддержка разных конфигураций
- Гибкость при изменении требований
